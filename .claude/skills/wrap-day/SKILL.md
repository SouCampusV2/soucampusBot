# Wrap Day

Ритуал конца сессии (по образцу SouCampus builds). Не спрашивать, что
записать, — самому разобрать разговор и рабочее дерево.

## Порядок действий

1. **Что изменилось:** `git status`, `git log` за сегодня, `git diff` и то,
   что решили в разговоре.

2. **`docs/CHANGELOG.md` — главный шаг.** Новая секция сверху
   `## ГГГГ-ММ-ДД — суть дня`. Писать причины, а не список коммитов: что было
   не так, почему так, что отвергли. Ошибки по дороге — отдельно и честно.
   День без кода, но с решениями — секция всё равно нужна.

3. **`CLAUDE.md`** — точечно: «Статус одним экраном» (подвинуть 🟢/🟡/🔴,
   дата сверки), «С чего начинать следующую сессию», «Что нужно от
   владельца». Заголовки сверять по факту файла.

4. **Остальные docs — по вопросу на файл:**
   - `docs/RULES.md` — выучили правило ценой потерянного времени?
   - `docs/SPEC.md` — сменился статус шага или поведение?
   - `docs/ARCHITECTURE.md` — новая кнопка, команда, колонка, таймер?
   - `docs/ROADMAP.md` — закрыта фаза или пункт? Вычеркнуть и в `CLAUDE.md`.
   - `docs/IDEAS.md` — новая идея вне фазы или идея уехала в работу (🟢)?
   - `README.md` (английский) — новая команда, зависимость, шаг установки?

5. **`TEMP.md`** — править без просьбы нельзя. Если правка сделала пункт
   неверным (кнопку переименовали, баг ⚠️ починили) — сказать в саммари и
   предложить пересобрать.

6. **Код цел** (если трогали код): `npm run check`, `npm test`. Упавшее не
   заметать — показать вывод.

7. **Коммит и пуш:**
   - `git branch --show-current` — коммитить в текущую (`dev`), на `master` не
     переключаться.
   - Сообщение о сути и причине, **без `Co-Authored-By`** (`docs/RULES.md`).
   - Мёрж в `master` — не часть ритуала, не предлагать автоматически.

8. **Саммари:** что сделали (по смыслу), что ждёт владельца (`TEMP.md`,
   `OWNER-TASKS.md`), что дальше по `CLAUDE.md`. Различать: проверено в
   Discord / написано, но не проверено / ждёт владельца.
