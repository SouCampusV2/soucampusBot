# BoCampus — план и статус

**BoCampus** (`BoCampus#2698`) — Discord-бот SouCampus для приёма заказов на
Minecraft-постройки: тикет → форма заказа → квоты фрилансеров → выбор
исполнителя → оплата → сдача → отзыв. Работает на нескольких серверах сразу,
каждый сервер настраивается командой `/setup`.

Место в компании: Discord — главный свой канал продаж (там владельцы
серверов, то есть покупатели), см. `Claude/SouCampusBuilds/BusinessDocs/BUSINESS.md`
→ «Каналы». Бот — то, через что заказ из Discord доходит до работы.

Этот файл держит только **активный план** и **текущий статус**. Всё стабильное
вынесено в `docs/` — открывать по необходимости:

- [`docs/RULES.md`](docs/RULES.md) — **обязательные правила каждой сессии**: как
  объяснять код, правила Discord API, база, git (ветка `dev`, коммиты без
  соавторства ИИ), язык интерфейса, как проверять.
- [`docs/SPEC.md`](docs/SPEC.md) — **что бот должен делать**: все типы тикетов и
  10 шагов заказа, со статусом у каждого шага. Главный ориентир по фичам.
- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — **как устроен код**: слои,
  роутер по `customId`, настройки сервера, база, таймеры, указатель «задача →
  файлы». Открывать перед новой кнопкой, командой или правкой схемы.
- [`docs/ROADMAP.md`](docs/ROADMAP.md) — фазы 0–5: от починки багов до
  бота уровня продукта и хостинга 24/7. Порядок и зачем он такой.
- [`docs/IDEAS.md`](docs/IDEAS.md) — бэклог идей вне текущей фазы.
- [`docs/CHANGELOG.md`](docs/CHANGELOG.md) — датированный дневник: что сделано и
  почему.
- [`docs/archive/`](docs/archive/) — документы, сделавшие свою работу
  (`cursorrules-v1.md` — исходная спецификация из Cursor). Читать как историю;
  при расхождении прав этот файл.
- [`TEMP.md`](TEMP.md) — **ручной чек-лист владельца**: что прокликать в Discord.
  Правит владелец; без просьбы отметки не трогать.
- [`docs/DEPLOY.md`](docs/DEPLOY.md) — **как бот живёт на VPS**: сервер, обновление,
  логи, бэкапы, правило «один токен — один процесс». Открывать перед любым
  деплоем и перед запуском бота локально.
- [`OWNER-TASKS.md`](OWNER-TASKS.md) — задачи владельца, которые кодом не
  закрываются: Developer Portal, тестовый сервер, хостинг.

## ⚠️ Что помнить при любой правке

- **Каждая кнопка — это публичная дверь.** Discord не проверяет, кто нажал:
  любой, кто видит сообщение, может нажать любую кнопку. Проверка «кто ты»
  — в начале КАЖДОГО обработчика: `ensureTicketClient` для клиента,
  `isManagerOrAdmin` для менеджера. Подробнее — `docs/RULES.md` → «Discord API».
- **Новый обработчик → тест в `tests/`** с отказом постороннему. Фейки Discord —
  `tests/helpers/fakes.js`, база в памяти — `tests/helpers/db.js`.
- **Права менеджера — только через `isManagerOrAdmin`**, никаких своих
  проверок по имени роли рядом.
- **Реакция на изменение тикета — подписка на `ticketEvents`**
  (`modules/tickets/events.js`), а не вызов из каждого обработчика.
  Карточка заказа обновляется по событию `status`; если меняется то, что
  она показывает, без смены статуса (квота, дедлайн, правка) —
  `refreshOrderCard` вызывается прямо.
- **Стадия тикета — только `tickets.status` через `transitionTicket`.**
  Новая стадия или переход — строка в `TRANSITIONS` (`TicketStatus.js`), а
  не новый флаг. `payment_confirmed`/`completed` — наследие: пишутся для
  отката, не читаются.
- **Цена-ориентир — €1.5 за блок стороны карты** (150×150 ≈ €225). Где бот
  говорит о цене, брать из `docs/SPEC.md` → «Цена», не придумывать.
- **Новая колонка = строка в `runMigrations`**, а не только в `schema.sql`:
  `CREATE TABLE IF NOT EXISTS` уже существующей таблице колонок не добавит.
