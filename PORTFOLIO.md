# Паспорт для портфолио — BotCampus

Что из этого проекта показывается в портфолио владельца
(`stavytskyi.vercel.app/projects/botcampus`, репозиторий `SouCampusV2/Portfolio`)
и откуда каждый факт. Портфолио **само сюда не лезет в код** — оно читает этот
файл (процедура `docs/PORTFOLIO-SYNC.md` в репозитории портфолио). Поэтому:

> **Обновлять этот файл в конце каждой сессии, где изменилось что-то видимое
> снаружи** (шаг в `wrap-day`): новая функция в Discord, новая цифра, сменился
> статус, появилась или закрылась цель. Нечего менять — поправить только дату
> сверки.

Правила (из брифа портфолио, `REDESIGN_BRIEF.md` разделы 2–3):
- **Только проверяемые факты.** У каждой цифры — дата и источник (команда,
  база, слово владельца). Нет источника — не писать.
- **Роль:** «I built it alone», без оговорок. Не утверждать «wrote every line».
  Условие — владелец проходит `docs/STUDY.md`.
- **Не для портфолио:** число участников сервера (решение 14.11), прогнозы
  («могло бы быть 100 человек»), список AI-инструментов, детали находок аудита.
- Текст для сайта — по-английски, B1–B2, короткие предложения.

## Что работает (для схем в case study)

Путь заказа и статусы: тикет (`form`) → форма → Submit (`open`) → квоты →
выбор билдера (`assigned`) → оплата менеджером (`paid`) → сдача (`completed`)
→ отзыв → закрытие (`closed`, удаление через 48 ч). Мост с сайтом: отзывы и
черновики портфолио на сайт по согласию клиента (подписанная очередь), посты
с сайта в каналы Discord. Схемы в портфолио — `components/diagrams/BotCampus.tsx`:
**если поменялся путь заказа или статусы — отметить это в журнале ниже**, чтобы
синхронизация перерисовала схему.
