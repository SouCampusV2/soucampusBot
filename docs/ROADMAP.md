# Дорожная карта — BoCampus

Крупные фазы и почему они идут в таком порядке. Оперативный статус — в
`CLAUDE.md`, что бот делает — в `SPEC.md`. Легенда 🟢/🟡/🔴 — в `CLAUDE.md`.

**Принцип порядка:** сначала бот, которому можно доверить настоящего
клиента (фазы 0–2), потом бот, которым хочется хвастаться (фаза 3), потом —
чтобы он жил без ноутбука (фаза 5 можно поднять раньше, если пойдут
настоящие заказы). Сначала то, где ошибка стоит денег или репутации.

## 🔴 Фаза 3 — Бот уровня продукта

То, что отличает «тикет-бот» от «инструмента студии». Каждый пункт —
отдельная мини-задача, порядок обсуждается с владельцем.

1. **Карточка заказа, а не лента сообщений.** Одно закреплённое сообщение в
   канале клиента, которое бот редактирует: статус-таймлайн по
   `tickets.status` (Form → Quotes → Assigned → Paid → Done), исполнитель,
   цена, дедлайн. Клиент в любой момент видит, где заказ.
2. **Оценка цены прямо в форме** по формуле сайта (`FirstTry/src/lib/pricing.ts`:
   €1.5 за сторону карты, срок по опорным точкам 150→7 дн, 400→14, 600→24.5).
   Поле size `150x150` → «примерно €225, ~1 неделя». Одна формула на сайт и
   бота — не копировать числа руками, а держать их в одном месте.
3. **Транскрипт при закрытии:** вся переписка тикета файлом в лог-канал
   менеджеров и клиенту в ЛС. Спор о том, что обещали, решается файлом.
4. **Лог-канал для менеджеров** (`/setup log_channel`): каждое действие из
   `action_log` строкой — кто, что, по какому заказу.
5. **`/orders` для менеджера:** открытые заказы с фильтром по статусу,
   просроченные сверху. **`/order`** для клиента — статус своего заказа.
6. **Профиль фрилансера:** средний рейтинг и число сданных заказов прямо в
   эмбеде квоты. Клиент выбирает не по цене вслепую.
7. **Прогресс от исполнителя:** кнопка «Post update» → скриншоты и текст в
   канал клиента карточкой. Для Minecraft-построек это главное, что клиент
   хочет видеть.
8. **Авто-гигиена:** тикет без заполненной формы 48 ч → напоминание, ещё
   24 ч → закрытие (через уже готовые `closeTicket` и уборщик).
9. **Маршрутизация заказов по команде:** заказ уходит в канал квот нужной
   группы (например, по типу постройки или размеру), а не во все сразу.
   Под будущую билд-тиму (решение 2026-10-25).
10. **Статистика `/stats`:** заказов за месяц, конверсия тикет → оплата,
   средний чек, средний рейтинг. Те же вопросы, что в `BUSINESS.md`
   «надо мерить».

## 🔴 Фаза 5 — Хостинг 24/7

**Где — решено 2026-10-25:** VPS владельца (Hostinger KVM 1, 4 ГБ), тот же,
где n8n и будущий `souc-scanner` сайта (`FirstTry/docs/SCANNER.md` § 4).

**Бюджет памяти** (по § 4 SCANNER.md + бот):

| Что | Память |
|---|---|
| n8n | ~0.7 ГБ |
| `clamd` (сканер) | ~1–1.5 ГБ, **вдвое** на минуту при обновлении сигнатур |
| Java-сервис сканера | ~0.3 ГБ |
| **BoCampus** | ~0.1–0.15 ГБ |
| **Итого** | **~2.7 ГБ из 4**, пик обновления ClamAV — впритык |

Следствия:
- боту — **жёсткий лимит памяти** (Docker `mem_limit: 256m` или
  `node --max-old-space-size=192`), чтобы утечка в боте не уронила сканер, и
  наоборот;
- **автоперезапуск** (`restart: unless-stopped` / `pm2`): если пик ClamAV
  вытеснит бота, он поднимется сам;
- swap 2 ГБ из плана сканера страхует и бота.

Шаги:
- Docker-образ (`node:22-alpine`, `npm ci --omit=dev`), `docker-compose`
  рядом со сканером, `.env` только на VPS.
- `bot.db` — в volume; ежедневный бэкап через `db.backup()` (не копированием
  файла под WAL).
- Логи в файл с ротацией, алерт в Telegram/Discord при падении.
- Деплой: `git pull && docker compose up -d --build` по SSH; позже —
  GitHub Actions после зелёного CI на `master`.

## Решения владельца

- **2026-10-25 — бот под будущую билд-тиму SouCampus.** Сейчас владелец
  работает один, но цикл с квотами от нескольких фрилансеров **оставляем**:
  тима появится, и заказы должны уже идти по каналам и тикетам. Тикеты —
  осознанный выбор как более организованный способ вести дела, а не
  временная схема «пока один». Следствие для фазы 3: маршрутизация заказов
  по каналам/ролям команды (например, по типу постройки) — в плане.
- **2026-10-25 — валюта €.** Бюджет в форме и цены — в евро, как на сайте
  (сделано в фазе 1).
- **2026-10-25 — границы бюджета остаются** (`<€100` / `€100–€500` /
  `€501–€1000` / `€1000+`). Ориентир цены — €1.5 за блок стороны карты,
  записан в `SPEC.md` → «Цена».
- **2026-10-25 — Team Application: заявитель видит свой канал.** Как в
  заказе: свой приватный канал, где он заполняет данные о себе и портфолио;
  видят он и менеджеры. Детали — `SPEC.md`.
- **2026-10-25 — хостинг на VPS владельца** вместе со сканером сайта
  (фаза 5).
