# Спецификация — что BoCampus должен делать

Продуктовое описание бота. Выросло из `archive/cursorrules-v1.md` (исходная
спецификация из Cursor) и сверено с кодом 2026-10-25. Статус у каждого шага —
по легенде из `CLAUDE.md`. Как это устроено в коде — `ARCHITECTURE.md`.

## Роли

| Роль | Кто | Как определяется |
|---|---|---|
| Client | кто открыл тикет | `tickets.client_id` |
| Freelancer | исполнители; роль выдаёт менеджер после одобрения | роль из `/setup freelancer_role`, иначе роль с именем «Freelancer» |
| Manager | ведёт заказы, подтверждает оплату | любой с правом Administrator + роль из `/setup manager_role`; пока роль не задана — роль с именем «Manager»/«Admin» |

## Цена — ориентир

**≈ €1.5 за блок стороны карты.** Карта 150×150 ≈ €225, 400×400 ≈ €600.
Для неквадратной — по стороне квадрата той же площади: √(ширина×высота)×1.5,
например 200×100 → √20000 ≈ 141 → ≈ €212.
Сроки — по опорным точкам: 150 → ~1 неделя, 400 → ~2 недели, 600 → ~3–4 недели.

Источник правды — формула сайта `FirstTry/src/lib/pricing.ts` (`BASE_RATE`,
`DEADLINE_ANCHORS`); здесь — копия для людей. Поменялась ставка на сайте —
поменять и тут. Это **ориентир, а не прайс**: финальную цену называет
фрилансер в квоте. Границы бюджета в форме (`<€100` … `€1000+`) этой формуле
не подгоняются — решение владельца 2026-10-25. Подсказка с оценкой прямо в
форме — фаза 3, п. 2.

## Настройка сервера — `/setup` 🟡

Только админ сервера. Значения хранятся в `guild_config`; что не задано,
берётся из `.env` (режим одного сервера).

`active_orders`, `quotes`, `archived` (категории) · `reviews` (канал) ·
`manager_role`, `freelancer_role` · `color` (цвет эмбедов) · `panel`
(опубликовать панель) · `view` (показать настройки).

Панель, опубликованная `/setup panel`, — постоянное сообщение; на старте бот
ничего не постит. Для `.env`-режима (`CHANNEL_TICKET_PANEL`) панель
публикуется, только если среди последних 50 сообщений канала нет нашей.

## Типы тикетов

### Order — полный цикл ниже
### Help 🟡
Приватный канал: клиент + менеджеры. 🔴 Нет кнопки «закрыть тикет».
### Team Application 🔴
Человек подаётся в билдеры. Решение владельца 2026-10-25: **заявитель видит
свой канал** — как клиент в заказе. Канал `apply-<ник>`: видят заявитель и
менеджеры, больше никто (исходная спецификация «только менеджеры» отменена).

План: кнопка **Fill application** → модалка (о себе, опыт, стиль/
специализация, часовой пояс, ссылки на портфолио) → summary-эмбед в канале с
**Edit application** (как Edit Order) → кнопки менеджера **Accept** (выдать
роль Freelancer, сообщение заявителю) / **Reject** (с причиной). Сейчас —
пустой канал, как Help.

## Цикл заказа

### Шаг 1 — Вход 🟢
Панель с кнопкой **Create Ticket** → меню типа (Help / Team Application /
Order) → кнопка **Confirm — <тип>** → канал `order-<username>` в категории
active_orders, видят клиент и менеджеры. Лимит: один тикет в 60 секунд.

### Шаг 2 — Форма заказа 🟢
Кнопка **Fill order form** → модалка Part 1 (need, deadline, reference_urls,
size, theme) → **Continue — version & details** → модалка Part 2 (version,
extra_details) → меню бюджета (`<€100` / `€100–€500` / `€501–€1000` /
`€1000+`). После summary повторное заполнение запрещено. Заполнять может
только клиент.

🔴 Дедлайн должен храниться **датой** (для напоминаний), сейчас — текст.

### Шаг 3 — Summary 🟡
Эмбед с ответами + **Edit Order** (модалка с заполненными полями, только
клиент). 🔴 Правка после создания канала квот до фрилансеров не доходит —
фаза 2.

### Шаг 4 — Канал квот 🟢
Через 60 секунд после summary: канал `quote-<имя>-building` в категории quotes,
видят Freelancer и Manager. Эмбед заказа **без имени клиента** + кнопки
**Submit Quote** / **Send Message** / **Not Interested**. Таймер переживает
перезапуск.

### Шаг 5 — Квоты 🟡
Квота (цена, срок, сообщение) → эмбед в канал квот и в канал клиента с
кнопками (нажимает только клиент): **Accept** (исполнитель назначен и
добавлен в канал клиента), **Contact freelancer** (приватный тред в
канале клиента + **Close discussion**), **Decline: price / portfolio /
deadline** (причина в `action_log` и сообщение в канал квот).

После выбора исполнителя квоты закрыты; у фрилансера не больше одной
ожидающей квоты (проверка и на кнопке, и в модалке).

### Шаг 6 — Переписка 🟢
**Send Message** фрилансера → эмбед в оба канала с кнопкой **Reply**; ответы
идут Discord-реплаем под предыдущее сообщение. Клиент подписан как «Client».

### Шаг 7 — Not Interested 🟡
Фрилансер теряет доступ к каналу (deny ViewChannel) и получает ЛС с именем
клиента.
🔴 Счётчик в канале клиента: «2 of 8 freelancers sent a quote, 1 declined».

### Шаг 8 — Оплата 🟡
После выбора исполнителя в канале квот — **Confirm Payment Received**
(только менеджер) → сообщения в оба канала + ЛС исполнителю → кнопка **Mark as
Complete**. Оплата только ручная.

### Шаг 9 — Дедлайн 🔴
Cron каждый день в 09:00: дедлайн в ближайшие 24 часа → напоминание в оба
канала + **Extend Deadline** (менеджер, модалка с датой). Код есть, но на
текстовых дедлайнах не срабатывает.

### Шаг 10 — Завершение и отзыв 🟡
**Mark as Complete** (менеджер) → в канал клиента «Your order is complete!» +
**Leave Review** (рейтинг 1–5, комментарий) → эмбед в канал reviews. Канал
квот → категория archived, только чтение. Канал клиента — удалить через 48 ч
или архивировать (выбор менеджера кнопкой).

Один отзыв на заказ. Канал квот закрыт на запись и для @everyone, и для
роли Freelancer. 🔴 Канал клиента не трогается — фаза 2 («Close ticket»,
удаление через 48 ч).
