# Спецификация — что BoCampus должен делать

Продуктовое описание бота. Выросло из `archive/cursorrules-v1.md` (исходная
спецификация из Cursor) и сверено с кодом 2026-10-25. Статус у каждого шага —
по легенде из `CLAUDE.md`. Как это устроено в коде — `ARCHITECTURE.md`.

## Роли

| Роль | Кто | Как определяется |
|---|---|---|
| Client | кто открыл тикет | `tickets.client_id` |
| Freelancer | исполнители; роль выдаёт менеджер после одобрения | роль из `/setup freelancer_role`, иначе роль с именем «Freelancer» |
| Manager | ведёт заказы, подтверждает оплату | любой с правом Administrator + роль из `/setup manager_role`; пока роль не задана — роль с именем «Manager»/«Admin» |

## Цена — ориентир

**≈ €1.5 за блок стороны карты.** Карта 150×150 ≈ €225, 400×400 ≈ €600.
Для неквадратной — по стороне квадрата той же площади: √(ширина×высота)×1.5,
например 200×100 → √20000 ≈ 141 → ≈ €212.
Сроки — по опорным точкам: 150 → ~1 неделя, 400 → ~2 недели, 600 → ~3–4 недели.

Источник правды — формула сайта `FirstTry/src/lib/pricing.ts` (`BASE_RATE`,
`DEADLINE_ANCHORS`); здесь — копия для людей. Поменялась ставка на сайте —
поменять и тут. Это **ориентир, а не прайс**: финальную цену называет
фрилансер в квоте. Границы бюджета в форме (`<€100` … `€1000+`) этой формуле
не подгоняются — решение владельца 2026-10-25. Подсказка с оценкой прямо в
форме — фаза 3, п. 2.

## Карточка заказа 🟡

Как только форма заполнена, в канале клиента появляется **карточка** — одно
закреплённое сообщение, которое бот редактирует: строка статуса, этапы
(✅ Order form → ▶️ Freelancer picked → ⬜ Paid → ⬜ Delivered), квоты
(«2 received · 1 not interested», пока идёт сбор), исполнитель, согласованная
цена, дедлайн с обратным отсчётом, оценка по размеру, бюджет. Обновляется на
каждом переходе статуса, новой квоте, отказе, правке и смене дедлайна.

Квота у клиента показывает **репутацию фрилансера на этом сервере**:
«⭐ 4.5 · 2 reviews · 3 orders delivered» или «🆕 New on this server».

Оценка цены («Estimate (guide)») — в summary, у фрилансеров и в карточке,
если размер читается (`150x150`, `200×100`, `about 400`); формула — «Цена»
выше.

## Транскрипт 🟡

При закрытии любого тикета (кнопкой, менеджером или авто-гигиеной) бот
собирает всю переписку канала — время (UTC), автор, текст, вложения,
содержимое своих эмбедов — в `transcript-<id>.txt` и отправляет в лог-канал
менеджеров и клиенту в ЛС. Канал удаляется через 48 ч, файл остаётся.
Без приватных тредов «Contact freelancer». Требует интента Message Content.

## Авто-гигиена 🟡

Заказ, застрявший на форме: через **48 ч** — одно напоминание клиенту с
временем закрытия; ещё через **24 ч** — автоматическое закрытие обычным
путём (архив, удаление через 48 ч, менеджер может оставить).

## Настройка сервера — `/setup` 🟡

Только админ сервера. Значения хранятся в `guild_config`; что не задано,
берётся из `.env` (режим одного сервера).

`active_orders`, `quotes`, `archived` (категории) · `reviews` (канал) ·
`log_channel` (лог для менеджеров: строка на каждое событие, без пингов) ·
`manager_role`, `freelancer_role` · `color` (цвет эмбедов) · `panel`
(опубликовать панель) · `view` (показать настройки).

Панель, опубликованная `/setup panel`, — постоянное сообщение; на старте бот
ничего не постит. Для `.env`-режима (`CHANNEL_TICKET_PANEL`) панель
публикуется, только если среди последних 50 сообщений канала нет нашей.

## Типы тикетов

Стадия тикета — колонка `status`, переходы — таблица в
`src/modules/tickets/TicketStatus.js`:

| Тип | Путь |
|---|---|
| Order | `form → open → assigned → paid → completed`, из любой — `closed` |
| Help | `open → closed` |
| Application | `open → accepted | rejected`, из любой — `closed` |

### Order — полный цикл ниже
### Help 🟡
Приватный канал `help-<ник>`: клиент + менеджеры. Закрывается кнопкой
**Close ticket** (см. «Закрытие тикета»).
### Team Application 🟡
Человек подаётся в билдеры. Решение владельца 2026-10-25: **заявитель видит
свой канал** — как клиент в заказе. Канал `apply-<ник>`: видят заявитель и
менеджеры, больше никто (исходная спецификация «только менеджеры» отменена).

Кнопка **Fill application** → модалка (About you, Building experience,
Styles / specialty, Timezone, Portfolio links; обязательны «о себе» и
портфолио) → summary-эмбед в канале с **Edit application** (заявитель, пока
не решено) и кнопками менеджера **Accept** (бот выдаёт роль Freelancer;
если роли нет или бот ниже неё в иерархии — пишет об этом в канал) /
**Reject** (модалка с причиной; причина уходит заявителю в канал и в ЛС).
Решение одно: второй Accept/Reject — «already decided».

## Цикл заказа

### Шаг 1 — Вход 🟢
Панель с кнопкой **Create Ticket** → меню типа (Help / Team Application /
Order) → кнопка **Confirm — <тип>** → канал `order-`/`help-`/`apply-<username>`
в категории active_orders, видят клиент и менеджеры. Лимит: один тикет в 60 секунд.

### Шаг 2 — Форма заказа 🟢
Кнопка **Fill order form** → модалка Part 1 (need, deadline, reference_urls,
size, theme) → **Continue — version & details** → модалка Part 2 (version,
extra_details) → меню бюджета (`<€100` / `€100–€500` / `€501–€1000` /
`€1000+`). После summary повторное заполнение запрещено. Заполнять может
только клиент.

Дедлайн хранится **датой** (`tickets.deadline` = `YYYY-MM-DD` или NULL),
исходный текст клиента — в форме. Понимает `2026-12-25`, `25.12.2026`,
`25/12/2026`, `tomorrow`, `[in] N days/weeks/months`. Нераспознанное
сохраняется, но клиент получает предупреждение «напоминаний не будет».

### Шаг 3 — Summary 🟡
Эмбед с ответами + **Edit Order** (модалка с заполненными полями, только
клиент). Правка возможна, пока заказ `open` — после выбора исполнителя
отказ: фрилансер назвал цену за то, что видел. Правка повторяется в канале
квот («The client updated the order»), без имени клиента.

### Шаг 4 — Канал квот 🟢
Через 60 секунд после summary: канал `quote-<имя>-building` в категории quotes,
видят Freelancer и Manager. Эмбед заказа **без имени клиента** + кнопки
**Submit Quote** / **Send Message** / **Not Interested**. Таймер переживает
перезапуск.

### Шаг 5 — Квоты 🟡
Квота (цена, срок, сообщение) → эмбед в канал квот и в канал клиента с
кнопками (нажимает только клиент): **Accept** (исполнитель назначен и
добавлен в канал клиента), **Contact freelancer** (приватный тред в
канале клиента + **Close discussion**), **Decline: price / portfolio /
deadline** (причина в `action_log` и сообщение в канал квот).

После выбора исполнителя квоты закрыты; у фрилансера не больше одной
ожидающей квоты (проверка и на кнопке, и в модалке).

### Шаг 6 — Переписка 🟢
**Send Message** фрилансера → эмбед в оба канала с кнопкой **Reply**; ответы
идут Discord-реплаем под предыдущее сообщение. Клиент подписан как «Client».

### Шаг 7 — Not Interested 🟡
Фрилансер теряет доступ к каналу (deny ViewChannel) и получает ЛС с именем
клиента.
Счётчик в канале клиента — одно сообщение, бот его редактирует:
«📊 Your order so far: 2 quotes received · 1 freelancer not interested».
Отказы считаются по разным фрилансерам. Без «из N»: число людей с ролью
требует привилегированного интента, его бот не просит (решение 2026-10-26).

### Шаг 8 — Оплата 🟡
После выбора исполнителя в канале квот — **Confirm Payment Received**
(только менеджер) → сообщения в оба канала + ЛС исполнителю → кнопка **Mark as
Complete**. Оплата только ручная.

### Шаг 9 — Дедлайн 🟡
Каждый день в 09:00 по `BOT_TIMEZONE` (по умолчанию Europe/Tallinn): заказы
`open/assigned/paid` с дедлайном сегодня или завтра → напоминание в оба
канала + **Extend Deadline** (менеджер; новая дата должна читаться и не
быть в прошлом).

### Шаг 10 — Завершение и отзыв 🟡
**Mark as Complete** (менеджер) → в канал клиента «Your order is complete!» +
**Leave Review** (рейтинг 1–5, комментарий) и **Close ticket** → эмбед
отзыва в канал reviews. Один отзыв на заказ. Канал квот → категория
archived, только чтение для @everyone и роли Freelancer. Канал клиента
остаётся открытым для отзыва и закрывается кнопкой.

## Закрытие тикета 🟡

Кнопка **Close ticket** — в приветствии любого тикета и в сообщении о сдаче
заказа. Закрыть может менеджер — всегда; владелец тикета — заказ до выбора
исполнителя (отмена) или после сдачи, Help и заявку — всегда. Между выбором
исполнителя и сдачей клиент закрыть не может: работа идёт, возможно
оплачена — решает менеджер.

При закрытии: статус `closed`; канал → archived, писать не могут клиент и
исполнитель; через **48 часов** канал удаляется. Менеджер может нажать
**Keep archived** — тогда канал остаётся. Заказ, закрытый до сдачи, закрывает
и канал квот. Удаляет уборщик раз в 10 минут (и сразу при старте), поэтому
удаление переживает перезапуск; отзывы и записи в базе не удаляются.
